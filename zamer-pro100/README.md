# Замер → PRO100: наработки (передача в новый чат)

Задача Макса (MGS Mebel): приложение для замерщика. Замерщик на телефоне/планшете фиксирует помещение
(длины стен, углы, высоты, окна, двери, розетки, выводы воды, щитки), а дизайнер открывает этот замер в **PRO100 7.08**.

## Что уже выяснили
- Родной формат PRO100 (`.sto`) закрытый, бинарный, документации нет. Генерировать его не стали.
- **Рабочий путь — импорт 3D-модели.** Генерируем комнату в формате 3DS (и OBJ) из размеров замера;
  Макс проверил: **в PRO100 7.08 файл открывается, всё работает** (26.10.2026).
- Стены приходят как импортированный объект (не «родные» стены PRO100) — для дизайнера это нормально:
  комната по замеру не меняется, мебель ставится внутрь.
- Единицы: генерируем два варианта — `*_mm.3ds` (миллиметры) и `*_cm.3ds` (сантиметры).
  Какой из них правильный в PRO100 Макса — уточнить (он ответил «всё работает», вариант не назвал).

## Как устроен генератор (gen_koridor.py)
- План задаётся цепочкой стен: длины + поворот на каждом углу (+ влево = внутренний угол, − вправо = внешний),
  помещение всегда слева по ходу, толщина стены — справа (снаружи).
- У внутренних углов стена удлиняется на толщину (закрывает угол), у внешних — нет (иначе торчит внутрь).
- Проёмы — вырезы (u0, u1, z0, z1) в стене; розетки/щитки — маленькие цветные боксы на внутренней стороне
  (красный — розетка, синий — вода, белый/чёрный — щитки).
- Пол — полигон по контуру, триангуляция ear-clipping (контур бывает невыпуклым).
- 3DS: имена объектов обрезаются до 10 символов (ограничение формата), Z вверх. OBJ: Y вверх.

## Конструктор замера (29.10.2026) — текущий вариант
Ссылка: https://maxkharlamov12345.github.io/-mgs-project/zamer/ — `zamer/index.html` (+ движок `zamer/geom.js` для .3ds).
Прежние варианты (форма с шагами, ниша по фото, обводка по фото) Макс забраковал и попросил удалить — удалены.
Три режима в одном окне (переключатель в шапке):
- **План** — только контур, БЕЗ размеров (замерщик их ещё не знает): чертит пальцем, только под 90° (шаг 50 мм), без шаблонов.
  Сетка приближается/отдаляется (два пальца, колесо, кнопки + − ⤢), один палец по пустому месту — сдвиг.
  Правка: касание угла — окно «угол» (90/270/точное число) и «Удалить угол» (стены сливаются, элементы переходят);
  касание стены — «Открыть развёртку», «Добавить угол здесь» (стена делится), «Добавить уступ здесь» (ступенька 300 мм);
  стену можно сдвинуть пальцем перпендикулярно (углы остаются прямыми). Длин на плане НЕТ (Макс: лишняя инфо), зато подписаны ВСЕ углы (90° серым, остальные красным).
  Кружок с номером стены (1, 2, 3…) → развёртка этой стены. Лаймовый кружок — длина введена.
- **Развёртка** — плоский вид стены изнутри (не вращается). ЗАМЕРЫ С ПРИВЯЗКОЙ К МЕСТУ (Макс 29.10): «↔ Длина» / «↕ Высота» →
  за пальцем бежит оранжевый пунктир (длина — по высоте, высота — вдоль стены, шаг 10 мм), отпустил → окно: ТОЛЬКО цифра
  замера, «＋ Ещё», «Удалить». Место (высота/отступ пунктира) — только для наглядности: цифрой не показываем и не спрашиваем (Макс). Замеров сколько угодно (хоть один). Пустой замер при закрытии окна удаляется.
  Данные стены: wd.lm = [{id, z, v}] (длины), wd.hm = [{id, u, v}] (высоты); старые len/hgt[3] переводятся в wd().
  Строится по ним: верх — ломаная через замеры высоты, правый край — завал по замерам длины; на плане — длина, замеренная
  ниже всех (lBase). geom.js: W.topPts / W.rendPts (interp, cell). Никакого «в расчёт». Кнопка 📷 — список замеров и фото.
  Слева меню элементов (категории как в замере maxbazis), касание стены → элемент → окно с полями; ДВИГАЮТСЯ ТОЛЬКО ЦИФРАМИ.
  У выбранного элемента на чертеже его размеры (оранжевые — примерные).
  Меню элементов открыто сразу (и на телефоне — снизу, на 44% высоты); чертёж всегда сжимается рядом/над меню и окнами, а не
  перекрывается ими (Макс 29.10). Если меню и окно вместе не влезают (телефон, планшет в портрете) — окно на время заменяет меню.
  Описание/примечание у каждого элемента. Справа сверху кнопки «＋ Элемент» (открыть/скрыть меню), «↔ Длина», «↕ Высота», 📷;
  кнопок перехода к соседним стенам нет (Макс 29.10) — стена выбирается на плане или в 3D.
- **3D** — демонстрация: все стены, элементы, все размеры и названия. Размеры НАРИСОВАНЫ НА ПОВЕРХНОСТИ СТЕН (canvas-текстура
  на каждую стену, как развёртка): тонкие линии с засечками точно по стене, текст без рамок, не крутится за камерой (Макс 29.10:
  плашки-спрайты были «мультяшно»); подписи раскладываются с обходом наложений (wallSheet) в два прохода: сначала все линии
  (препятствия), потом цифры — цифра не ложится на линии; по стеклу окна можно, по рамке нет. Высоты всегда с «h» (h 2700) и
  стоят в верхней части стены (Макс 29.10).
  Стены между камерой и комнатой прозрачные, их подписи скрыты. Касание стены — выделяется (подсвечивается только лицевая поверхность — тонкий слой w.hl, не вся толщина, иначе рябь на стыках; + подсказка + кнопка
  «Открыть развёртку»), повторное касание той же стены → развёртка (Макс 29.10: случайно открывалась).
- Углы стен — стык «на ус» (geom.js extAt/lbox: наружная грань продлена на T/tan(угол/2), внутренняя кончается в углу;
  90° → +T, 270° → −T) — стены не заходят друг в друга (Макс 29.10), так же и в .3ds. Обводки рёбер у стен нет.
- «Проверка»: что не введено (длины/высоты в 3 местах, поля элементов, фото), .3ds (мм/см) для PRO100, JSON с фото.
  Хранение — localStorage (`mgs-room-v3`). Длина в замкнутой комнате: разницу забирает встречная параллельная стена.
- Дальше (мысль Макса): та же модель — основа для его конструктора мебели в CRM.
