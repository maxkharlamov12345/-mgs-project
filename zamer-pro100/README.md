# Замер → PRO100: наработки (передача в новый чат)

Задача Макса (MGS Mebel): приложение для замерщика. Замерщик на телефоне/планшете фиксирует помещение
(длины стен, углы, высоты, окна, двери, розетки, выводы воды, щитки), а дизайнер открывает этот замер в **PRO100 7.08**.

## Что уже выяснили
- Родной формат PRO100 (`.sto`) закрытый, бинарный, документации нет. Генерировать его не стали.
- **Рабочий путь — импорт 3D-модели.** Генерируем комнату в формате 3DS (и OBJ) из размеров замера;
  Макс проверил: **в PRO100 7.08 файл открывается, всё работает** (26.10.2026).
- Стены приходят как импортированный объект (не «родные» стены PRO100) — для дизайнера это нормально:
  комната по замеру не меняется, мебель ставится внутрь.
- Единицы: генерируем два варианта — `*_mm.3ds` (миллиметры) и `*_cm.3ds` (сантиметры).
  Какой из них правильный в PRO100 Макса — уточнить (он ответил «всё работает», вариант не назвал).

## Как устроен генератор (gen_koridor.py)
- План задаётся цепочкой стен: длины + поворот на каждом углу (+ влево = внутренний угол, − вправо = внешний),
  помещение всегда слева по ходу, толщина стены — справа (снаружи).
- У внутренних углов стена удлиняется на толщину (закрывает угол), у внешних — нет (иначе торчит внутрь).
- Проёмы — вырезы (u0, u1, z0, z1) в стене; розетки/щитки — маленькие цветные боксы на внутренней стороне
  (красный — розетка, синий — вода, белый/чёрный — щитки).
- Пол — полигон по контуру, триангуляция ear-clipping (контур бывает невыпуклым).
- 3DS: имена объектов обрезаются до 10 символов (ограничение формата), Z вверх. OBJ: Y вверх.

## Приложение замерщика (сделано 28.10.2026)
Ссылка: https://maxkharlamov12345.github.io/-mgs-project/zamer/ — файлы `zamer/index.html`, `zamer/app.js`, `zamer/geom.js`.
Логика и структура — по образцу maxbazis.com/zamer (разобрали по видео Макса), своя реализация и стиль MGS:
- Шаги-вкладки: Объект → Стены → Помещение → Проверка → Чертёж 2D → 3D → Файлы.
- Стены обходим по часовой: стоим лицом к стене 1 (с входной дверью), следующая — справа; размеры от ЛЕВОГО угла.
  Каждая стена: длина в 3 точках (низ/середина/верх), высота в 3 точках (слева/центр/справа), в расчёт — наименьшее;
  угол со следующей (90 — обычный, 270 — внешний, можно точное значение).
- «Что есть на стене» — 8 категорий, каждую надо закрыть («Нет на стене» или «+ Добавить»): окна/двери/проёмы, электрика,
  вода, газ, отопление, вентиляция, ригели/колонны/короба, прочее (необязательно). Элемент: от левого/правого угла,
  положение, размеры (у проёмов — по 3 точкам), откос, подоконник, открывание, примечание, фото.
- Проверка: ошибки (обязательное) и замечания, клик — переход к месту; чек-лист «Перед уходом с объекта».
- Файлы: .3ds мм / см (для PRO100), OBJ+MTL (zip), JSON замера с фото (открывается в приложении), PDF через печать, zip «всё сразу», «Отправить» (share).
- Хранение только на устройстве: localStorage (замер) + IndexedDB (фото). На сервер ничего не уходит.
- Геометрия и экспорт — `zamer/geom.js` (тот же принцип, что Python-генератор ниже; проверен в PRO100 7.08).
- Тест: Playwright iPhone 13 — новый замер коридора, 5 элементов, 2D/3D, выгрузка .3ds/.json/.zip — без ошибок.

## Замер ниши — пример (28.10.2026)
`zamer/nisha.html` (…/-mgs-project/zamer/nisha.html), пример — фото ниши с коллектором от замерщиков (`zamer/nisha-primer.jpg`, цифры условные).
Поток: фото → 4 угла проёма пальцем (гомография: фото «выпрямляется», отметки на фото дают размеры ≈) → по одному вопросу с подсветкой на фото:
ширина ×3, высота ×3, глубина в 4 углах (от плоскости плитки), откосы Л/П/верх (+ верх в плоскости / выступает / утоплен), от пола до низа, от угла →
«что внутри»: тип → 2 касания по углам → X, Y, Ш, В (с подсказкой ≈ по фото, «Принять»), выступ от задней стены, нужен ли доступ →
итог: свободная глубина (глубина задней стены в месте элемента − выступ, минимум) и что ограничивает; виды спереди / разрез сбоку / сверху, 3D, .3ds для PRO100, бланк в PDF.
Хранение — localStorage (одна ниша). Офлайн/без нейросети. Идея Макса: фото → размеры по шагам; это и есть прототип такого формата.

## Замер по фото — единый формат (29.10.2026)
`zamer/foto.html` (…/-mgs-project/zamer/foto.html), пример — фото коридора (`zamer/koridor-primer.jpg`) + цифры бумажного бланка.
Идея Макса: один формат для любых помещений; слева фото, справа сразу 3D; размеры появляются стрелками на 3D.
- Этап 1 «Обвести»: касания по углам слева направо — пол, потом потолок в том же углу → каждая пара соседних углов = стена (четырёхугольник на фото).
  Углы внутри фото угадываются: внутренний угол дальше от камеры → его вертикальное ребро на фото короче, чем у соседей (внешний — длиннее).
  Несколько фото = продолжение обхода по часовой. Элементы (окно, дверь, проём, ниша, розетка, щиток, ХВС/ГВС, слив, стояк, радиатор, короб…) — касанием по фото, стена определяется сама.
  3D строится сразу по пропорциям обводки (оценка длины = ширина стены на фото / её высота × 2700).
- Этап 2 «Размеры»: по одному вопросу (длины, высоты, углы, у элементов — от угла, от пола, ширина, высота, глубина/выступ), с оценкой «≈ по фото».
  Текущий размер — оранжевым на фото и на 3D; камера сама поворачивается к стене, которую меряют; введённые — стрелки с подписями на 3D.
- Этап 3 «Итог»: что не подписано, .3ds (мм/см) для PRO100, JSON. Геометрия — тот же geom.js (ниша теперь вырез-углубление, kind 'recess').
- Хранение — localStorage (фото внутри, сжатие 1400px q0.72).
