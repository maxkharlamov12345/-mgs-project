# MGS Mebel — сайт (кухни, шкафы, гардеробные)

Сайт: https://maxkharlamov12345.github.io/-mgs-project/ (GitHub Pages, ветка `main`, корень репозитория).
Каждая страница — статический HTML без сборки. Медиа в `assets/`.

## Стиль (держать на всех страницах)
- Фон `#0f0e0c`, текст `#f4f1ec`, панели/карточки `#151311`, акцент `#bfd630` (цвет из логотипа).
- Шрифт Onest (Google Fonts), веса 300/400/500/700.
- Теги/плашки поверх фото — высота 32px, скруглённые, светлые.
- Лента в стиле Pinterest: до 4 колонок, колонки заканчиваются ровно, на телефоне 2 колонки.
- Минимум текста, крупные фото, тёмный фон «во всю страницу». Шапку на странице проекта убрали по просьбе Макса.
- Адаптив: телефон / планшет (<1000px — вертикальный просмотр) / ПК. Проверять на iPhone SE, iPhone 13, iPad, 1280×720, 1920.

## Работы с etopodbor.ru (#ЭТОКУХНИ — сайт Макса)
- Макс присылает ссылки вида `etopodbor.ru/product/<id>`: берём фото и описание, цену придумываем (тест).
- Текст и параметры — из страницы: данные в `<script type="application/json">` (Nuxt), объект `$sproduct`
  (`description`, `media[].url`, `attributeIds` → названия через `$sattributes`). Скрипт: скачать HTML с etopodbor.ru (домен разрешён).
- Фото лежат на `подбор-кухни.рф:3010/storage/...` — из облака недоступно. Забираем через встроенный браузер
  на Маке: открыть страницу, в JS сжать картинки canvas'ом (≤1200, q0.74), скачать в «Загрузки»
  (сохраняются под скрытыми именами `.Q6L2SF6YDW.com.anthropic.claudefordesktop.*`), затем device_stage_files.
- Отдельная работа (не комплекс) — запись в `projects()` с `complex: false`, `href: ''`; медиа `assets/k<id>-N.jpg`.

## Медиа и скорость
- Портфолио при открытии НИЧЕГО не качает заранее (раньше качались все фото и все полные видео — ~46 МБ):
  плитки — превью `assets/t/<имя>.webp` (960px, WebP q82 — 640/q72 Максу было мутно на Retina), фото изделия подгружаются
  только при открытии просмотра / в фоне, видео-обложки и их постеры — только когда плитка подходит к экрану.
  **После добавления новых фото (и после `make_minis.sh`) — `python3 tools/make_thumbs.py`** (делает превью).
  Полные фото в просмотре — ОРИГИНАЛЬНЫЕ JPEG (WebP-копии полных фото пробовали q76 и q85 — Максу заметна разница, убрали;
  `webp()` теперь ничего не меняет). Постеры видео-плиток — тоже из `t/` (`tilePoster()`).
  Портфолио: когда плитки открытой ленты загрузились, в фоне по одному прогреваются полные фото её изделий
  (порядок: изделия на экране, потом ближайшие к нему — пересчёт при прокрутке; у каждого сначала 3 фото, видные в слайдере:
  главное, второе, последнее; потом остальные. На страницах проектов — по изделиям в порядке ленты, так же 3 фото первыми; `bgPhotos()` → сразу в `mem` (blob-ссылка, без декодирования), иначе
  просмотр показывал у соседних фото незагруженные превью и они «появлялись через мгновение»; при saveData/2g — нет).
  Грузится только то, что на экране и чуть ниже: фото — `watchNear()` (IntersectionObserver, экран ниже; следим по паре плитка+фото — плитки переиспользуются при смене ленты; до этого у плитки
  пустышка), видео — ~20% экрана ниже. При прокрутке подгружается по мере подхода.
- Фото: JPEG ≤1200px, q74, progressive — их и показываем в просмотре; WebP только у превью ленты.
- `assets/dims.js` (`window.MGS_RATIOS` — высота/ширина каждого фото; делает `make_thumbs.py`) подключён во всех страницах:
  слайдер просмотра сразу знает размеры фото и не перестраивается, пока они догружаются (раньше соседние фото
  «менялись» через секунду). Плюс `snapSoon()` — после загрузки любого снимка слайдер встаёт точно на текущее фото.
- Страницы проектов (index, project-N) — так же, как портфолио: в ленте превью `t/*.webp` (960px, `loading="lazy"`), полные фото
  после загрузки первого экрана тихо докачиваются в фоне по одному (`preloadPhotos([], 1)`); при открытии просмотра — сначала
  фото открытого изделия, по 3 за раз. В просмотре, пока полное фото не готово, показывается превью из ленты (и в портфолио),
  полные видео в фоне больше НЕ качаются — играют потоком при открытии.
- Шрифт Onest — свой, `assets/fonts/*.woff2` (вариативный, урезан до нужных символов; ₽ — отдельный файл 1 КБ),
  `@font-face` и preload в `<head>` каждой страницы. Google Fonts не используем (минус 2 сервера при открытии).
- Шаблон страницы лежит в `<template data-dc>` (а не `<x-dc>`): браузер не ходит по адресам `{{p.src}}` (было ~10 запросов
  в никуда на страницу); `support.js` пропатчен искать `x-dc,template[data-dc]`. `window.__resources={}` в `<head>` — движок
  не скачивает страницу второй раз. Новые страницы делать так же.
- Кэш ВКЛЮЧЁН (20.10, после теста Макса «как новый пользователь»): `sw.js` = копия `tools/sw-cache.js`,
  в `<head>` всех страниц (вкл. home.html) — регистрация `navigator.serviceWorker.register('sw.js')` на load.
  Чтобы снова выключить: в `sw.js` — «убийца» кэша, в `<head>` вместо регистрации — снятие (unregister + caches.delete).
  `tools/sw-cache.js` — кэш в браузере (GitHub Pages даёт кэш всего 10 мин): фото/шрифты — сразу из кэша + фоновое обновление;
  страницы и js — сначала сеть (правки видны сразу), сеть молчит 3 с — из кэша; mp4 не трогает. Регистрируется в `<head>`.
- Портфолио: при наведении/касании плитки проекта его страница заранее качается (`rel=prefetch`).
- Видео: 720p H.264, `+faststart`. Для ленты — превью `<id>-preview.mp4` (первые 10 с, без звука, 540px).
  Полные видео играют потоком только в режиме просмотра, заранее не качаются.
- Видео в ленте запускаются только когда видны на экране.
- Загрузка ПО ПОРЯДКУ, как стоят плитки (сверху вниз, слева направо), во всех лентах: фото — по 2 одновременно (`pumpImg()`),
  видео — по одному (`pumpVid()`, следующее — когда у текущего появился кадр). Подложки видео-плиток (`vid-ph`) идут в очередь фото.
- Если начало рилса — заставка/рамка/скриншот, превью для ленты и обложку берём с первого «чистого» кадра
  (у `p2-kitchen-reel-1` — с 10-й секунды, у `p2-bedroom-reel-1` — с 3-й), полное видео не режем.

## Публикация
Коммит в `main` → GitHub Pages сам пересобирает сайт за ~1 минуту.
**Перед каждым пушем, где менялся код страниц — `python3 tools/tests/check.py`** (~5 мин; `quick` — ~1,5 мин без
проверок на медленном интернете). 8 проверок того, что уже ломалось: файлы/превью/dims, ошибки и 404 на всех страницах
(телефон+ПК), скорость первого экрана, пустые плитки при смене лент, «играет одно видео», видео после просмотра,
слайдер не перестраивается на медленном интернете, фоновая докачка. Красное — не пушить, чинить. Новый баг — добавить проверку.
Дотошный обход (видео на самом деле играют, ищет чёрные кадры, прыжки вёрстки, 5 экранов) — `tools/tests/qa/README.md`;
запускать после изменений в видео/просмотре/лентах.
- Видео в ленте страниц проектов и в просмотре (везде): под видео картинка его первого кадра (лента — `vid-ph`, просмотр —
  CSS-фон `t.pt`), заставки всех видео страницы качаются сразу после загрузки — Safari иначе мигает чёрным при запуске/повторном заходе.
**Каждую правку сразу коммитить и пушить в `main`, не спрашивая** (так попросил Макс). Превью в чат — по-прежнему.

### Главная — ПЕРЕПИСАНА С НУЛЯ (22.10, вместо всех прежних заплаток со scroll-snap)
- Страница НЕ прокручивается (html/body overflow:hidden). `<main class="stage">` fixed, высота 100lvh; 5 экранов `.screen` лежат друг на друге (absolute inset:0), видим только текущий (`.vis`).
- Единственный источник правды — `cur`. Переход `go(i)`: целевой экран выезжает (translate3d, 620 мс), старый уезжает; во время перехода новые нажатия ставятся в очередь (`queued`, берётся последнее).
- Свайп — свой (touchstart/move/end на .stage, экран тянется за пальцем, порог 16% высоты или быстрый флик). Вбок — не трогаем (лента «Списком»), два пальца — карта. Внутри прокручиваемого (форма расчёта, карточка салона) сначала прокручивается оно, на краю — переход.
- Колесо/тачпад: один жест = один экран (пауза >200 мс — новый жест). Ctrl+колесо — карте. Клавиши ↑↓ PgUp/PgDn Space Home End.
- Док: обычный click → go(). Подсветка ставится сразу при go() — без вычислений по прокрутке.
- Видео: загружены текущий и соседние экраны, играет только текущий (syncMedia после перехода).
- Адрес: #salons, #calc и т.д. открывают нужный экран; при переходе адрес обновляется через replaceState.
